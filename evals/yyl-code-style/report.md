## 格式和范例

- skill-creator 的 quick_validate.py 接受技能名称、frontmatter 和正文；本地引用路径检查通过。
- 三个 PHP Few-shot 块均在 PHP 8.2.33 下通过 `php -l`。代码使用目标 PHP 8.1 支持的语法，但本机没有实际 PHP 8.1 运行时。
- 第一组模板用内存数据替身运行：确认 data/code/msg、包装入参、应用/用户范围、数字输出、批量标记查询，以及非法参数不会查询数据。
- 第二组模板用本机回调/日志替身运行：明确的可选读取故障返回空列表；日志不可用不破坏这个降级；其他异常和必要结算失败继续抛出。
- 第三组事务模板仅进行 PHP 语法及人工边界检查，没有调用真实数据库验证事务隔离、竞争或故障恢复。

## 独立应用样本

技能写作前，一个新上下文代理仅收到虚构的 PHP 8.1/Lumen 9 项目事实，完成列表接口、错误/幂等边界和其他语言迁移三个任务。技能写作后，另一个新上下文代理读取本技能，再完成相同请求；未读取真实 video_api、基线输出或预期答案。

基线列表实现采用猜测的 `[code, data]` 元组和已拆包输入，另写 make() 并加入 strict_types。基线备注明确将这些视为待确认假设。对照真实来源的接口习惯，这些假设不能直接落入目标项目。技能样本保留 data/code/msg、既有 Version/Business 入口和包装边界，并注明真实方法名、启用状态常量和 schema 仍需核对；没有创建新响应格式或额外分页参数。

两组在批量查询、必要支付失败传播、幂等结果重放和 TypeScript 原生响应结构方面都给出了合理处理。技能样本进一步体现中文业务注释、短数组默认偏好、构造注入与项目实例入口的条件性使用；TypeScript 场景保留本项目 envelope/注入，并不复制 Lumen 分层。

技能样本的本机内存替身检查覆盖：列表范围/排序/50 条上限、批量标记和空列表；可选故障降级、日志故障、必要写入和提交失败、同连接回调、重放/参数冲突；TypeScript ID 合法性、顺序/重复项、响应外壳及错误传播。TypeScript 使用 Node 的类型剥离运行，未进行 tsc 静态类型检查。

这是每组一个代理、三个虚构请求的定性检查；没有重新执行真实业务、没有测量统计意义上的风格还原准确率、路由收益或模型性能提升。内存替身不是 Lumen/Eloquent/数据库/Redis 的集成验证，不能证明生产并发安全。技能是条件性的表达与实现指导，现有项目规则和真实契约仍具有优先级。
