# 场景 A 转换与验收计划

正文可用宽度由本场景资料确认为 **960px**。`table-A.md` 使用已声明支持的 Markdown 内嵌 XML，直接表达浅灰表头、加粗居中、正文左/顶部对齐与像素列宽；XML 未放进代码块。

- 两列表为 **3 行 × 2 列**：项 **240px**、说明 **720px**，总宽 **960px**。
- 三列表为 **3 行 × 3 列**：字段 **240px**、类型 **160px**、说明 **560px**，总宽 **960px**。

说明列保留更多空间；两张表总宽相同，目标均为正文左右边界。`&` 与 `<` 在 XML 中分别写为 `&amp;` 和 `&lt;`，转换后应显示原始字符。

1. 后续获得写入授权时按工具契约批量转换为可编辑的原生文档；提供标题字段时将首行文档名称映射到标题。
2. 利用可读回的原生结构与格式核对两张表的行列数、全部数据、5 个表头的浅灰/加粗/居中、正文左/顶部对齐，以及列宽分别为 `240+720=960`、`240+160+560=960`。
3. 集中确认正文左右边界与两张表对齐，正文单元格白底、自然换行、细浅灰网格边框和紧凑行距；检查说明文字无裁切、横向溢出或实体源码残留。默认边框等尚未观察的结果在此验收，不预设手工排版。仅发现实际缺失时局部补齐已转换表格。

实际限制：本次仅生成并本地核对 XML 与列宽数值，未发布、操作浏览器或验证飞书原生转换效果。960px 是本场景给定正文宽度，不能复用为其他文档的固定宽度。
