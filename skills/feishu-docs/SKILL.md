# 飞书文档编写

先生成格式完整、适合飞书转换的 Markdown，再按需批量写入原生文档。Markdown 已支持的格式在生成阶段完成；转换链路无法表达的原生格式最后局部补齐。本技能提供操作指引，不自带账号、权限或连接器。

## 总原则：原生优先，简约输出

- **Markdown 优先，原生结果，简约输出。** 优先在 Markdown 中使用目标工具支持的飞书/Lark 格式，包括已确认支持的原生扩展。浏览器用于最后补齐无法转换的格式和必要验收。
- 先表达结论和必要信息，删去重复铺垫。根据内容长度组织章节，短文可以直接用正文和列表，不套用固定的大纲。
- 格式服务于理解：并列项用列表，多字段对照用富文本表格，确有必要时再加高亮块、图表或公式。避免堆叠装饰、强调样式和无意义的空白。
- 交付反馈也保持简短：给实际文档链接、主要改动和必要的验证或限制说明，不默认附上长篇操作过程。

## 先生成 Markdown，再写入

1. 判断交付范围：只生成 `.md` 时直接完成本地内容，无需登录飞书、寻找目标文档或打开浏览器。需要编辑已有云文档时先读取目标和必要分页，保留不属于本次修改的内容。
2. 按 [写作原则](references/writing-principles.md) 组织简约正文，按 [Markdown 工作流](references/markdown-workflow.md) 选择格式。目标转换能力已有说明时直接沿用；未知时生成通用 Markdown，并列出原生格式待补齐项，不为起草先打开浏览器试样式。
3. 在生成阶段写好标题层级、列表、强调、链接、表格及带语言的代码围栏。目标工具支持飞书 XML 扩展时，高亮块、下划线等也直接写入 Markdown；普通导入器不支持的扩展不要硬套。
4. 用户要求写入飞书时，按 [工具适配](references/tool-adapters.md) 优先使用 MCP、CLI、API 的 Markdown 批量创建/更新或文件转换。长文按实际限制分批。上传为普通 `.md` 文件不等于创建了可编辑的飞书原生文档。
5. 写入后读取实际转换结果；只补齐待办清单中的原生格式。能通过原生工具补齐就使用工具，必要时最后用浏览器处理这些局部项。已转换的标题、列表、表格和代码块不逐项重新排版。
6. 完成一次集中验收；仅修正实际发现的问题。不反复打开浏览器试样式，也不把整篇纯文本粘贴后再逐段改格式作为默认流程。批量路径不可用时交付完整 Markdown 和具体缺口，说明无法完成云端写入。

## Markdown 与原生结果的约束

- 独立 Markdown 可以有一行文档名称；写入时按工具契约映射到标题字段，避免正文重复标题。章节使用真实标题层级，正文重点用行内强调。
- 顺序步骤使用有序列表，并列项使用无序列表；任务列表语法依目标转换契约选用。复选框不等于带负责人和截止日期的完整任务对象。
- 风险使用原生高亮块（callout）；引用块和文字底色不能冒充。已支持的飞书扩展直接生成，未支持时列为局部补齐项。
- **Markdown 中先生成完整表格；云端结果必须是原生富文本表格。** 基础表格使用管道语法和行内富文本，复杂表格采用目标工具文档支持的扩展。行数包括表头。只有转换未涵盖所需结构或样式时才局部补齐，详见 [原生格式](references/native-format.md)。
- 代码围栏标注语言，使转换后保留原生代码块和语言。下划线用受支持的扩展或最后的显式样式，不将双下划线当成通用下划线语法。
- 图表、公式、提及和文档引用按需要使用已支持语法。Mermaid 源码只有经支持的渲染链路处理才算图表；普通代码块不会自动成为流程图。
- 无法完成的原生格式明确标注，不把 Markdown 草稿、纯文本写入或普通文件上传宣称为已经完成的原生文档。

## 技术方案的必要交付

- 涉及新增数据库表时，提供完整的 `CREATE TABLE` SQL，包含字段类型、主键、必要的约束与索引。遵循项目已有数据库类型、版本和命名习惯；优先查阅现有表结构或迁移文件，缺失信息明确标注为待确认。文档中的富文本表格不能代替建表 SQL。
- 涉及接口时，先查阅项目的接口规范、OpenAPI、响应模型或现有实现，按实际约定给出响应字段和 JSON 示例，保持字段名、层级、类型、分页及错误响应一致。简要说明方法、路径及必要请求参数；只补充本次涉及的接口内容，不自行套用统一的 `code/message/data` 等结构。规范缺失时明确标为待确认或建议草案。
- 生成阶段就用 `sql`、`json` 语言的代码围栏承载示例，转换后验收原生代码块及语言。保持示例与文字、表结构及接口字段说明一致；这些必要交付不因“简约”而省略。

## 编辑已有内容

先读全相关区域和分页，确定唯一目标块或单元格。出现重名章节或无法辨认的目标时先澄清；禁止猜测块 ID。

仅修改用户要求的区域，保留其他段落、顺序、链接和单元格富文本。为变更区域准备 Markdown 或必要增量数据；单元格等局部编辑不为了 Markdown 工作流重建整篇文档。完整替换需要用户明确要求。

拆分较大写入。遇到超时、部分成功或重试，先读回已完成的内容再补缺项，防止重复段落、重复表格和误覆盖。

## 读回验收

检查文档标题、标题层级与目录、段落、列表、高亮块、代码语言及链接。表格必须检查 **原生表格结构、行列数、各单元格内容和关键行内样式**。单纯返回纯文本不能证明格式成功。

工具返回可靠的结构或格式结果时按其契约验收；否则读取块结构或查看渲染后的编辑器。记录无法观察的格式，不将“调用成功”当成“格式已验证”。

只生成 Markdown 时返回文件和必要的原生补齐说明；已写入时返回实际文档链接、主要改动和验证结果。未实际验证的功能不要宣称通过。文档写入权限不自动授权更改分享设置或发送通知。
