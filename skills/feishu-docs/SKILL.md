# 飞书文档编写

把内容写入飞书原生文档，并检查实际格式。优先使用已连接的飞书工具；工具能力不足时使用已授权的浏览器编辑器。本技能提供操作指引，不自带账号、权限或连接器。

## 先判断内容结构和工具能力

1. 确认新建还是编辑、目标文档和预期内容。已有链接时先读取目标文档，不凭标题猜测身份；没有必要的信息才向用户询问。
2. 阅读 [写作原则](references/writing-principles.md)，先拟定章节和内容，再选择原生格式。使用真实标题层级形成目录；正文保持正文，用加粗或高亮强调。
3. 按 [工具适配](references/tool-adapters.md) 检查实际可用的连接器、API 或浏览器。查看工具契约和能力，尤其确认表格、样式和读回支持。不能仅凭“支持 Markdown”推定全部原生格式可用。
4. 选择最小有效格式集合；按 [原生格式](references/native-format.md) 将段落、列表、风险、表格和代码映射到实际内容块。

## 写入原生文档

- 文档标题使用标题字段；正文中的章节使用相应标题块。除非用户要求，不重复插入一份文档标题。不要为了字号大把正文改成标题。
- 顺序步骤使用有序列表，并列内容使用无序列表，待办使用原生任务列表。复选框不等于具备负责人和截止日期的完整任务对象。
- 风险或提示使用原生高亮块（callout）；引述使用引用块。文字底色不等于高亮块。
- **表格默认且必须使用文档内的原生富文本表格。** 单元格可以保留加粗、链接和其他支持的富文本。不能用 Markdown 管道表格、制表符正文、电子表格或多维表格冒充。
- 创建表格时，行数包括表头。先建立表格，获取真实单元格身份或 UI 位置，再填内容和样式。只在工具明确保证转换时允许 Markdown 中间表示，写入后仍要检查生成的是原生表格。
- 代码使用原生代码块并设置语言。下划线使用显式样式；不要假设 Markdown 的双下划线能实现下划线。
- 图表、公式、提及和文档引用按需要使用。Mermaid 需要受支持的图表能力或插件；普通代码块不会自动成为流程图。
- 如工具无法实现必需格式，切换到支持的原生 API 或浏览器。仍不可用时，明确说明缺失能力并提供内容草稿，不声称完成原生写入，也不悄悄换成另一种产品。

## 编辑已有内容

先读全相关区域和分页，确定唯一目标块或单元格。出现重名章节或无法辨认的目标时先澄清；禁止猜测块 ID。

仅修改用户要求的区域，保留其他段落、顺序、链接和单元格富文本。只改变文字时，尽可能保留现有行内样式；完整替换文档需要用户明确要求。

拆分较大写入。遇到超时、部分成功或重试，先读回已完成的内容再补缺项，防止重复段落、重复表格和误覆盖。

## 读回验收

检查文档标题、标题层级与目录、段落、列表、高亮块、代码语言及链接。表格必须检查 **原生表格结构、行列数、各单元格内容和关键行内样式**。单纯返回纯文本不能证明格式成功。

工具返回可靠的结构或格式结果时按其契约验收；否则读取块结构或查看渲染后的编辑器。记录无法观察的格式，不将“调用成功”当成“格式已验证”。

完成后返回实际文档链接、主要改动和验证结果。尚未写入时明确标注草稿；未实际验证的功能不要宣称通过。文档写入权限不自动授权更改分享设置或发送通知。
