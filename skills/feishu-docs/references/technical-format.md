# 技术方案：接口与新增数据表

来源：用户指定参考文档的 **3.1 接口设计**、**5.1 新增数据表**，2026-10-12 已读取并核对展示结构。以下为格式归纳和虚构示例；原文业务内容与私有文档地址不纳入公开技能。

## 接口：沿用 3.1 的组织方式

每个本次新增或修改的接口按以下顺序组织，章节编号服从目标文档，不固定为第三章：

1. **标题**：编号、行内代码接口名、中文用途、变更属性（新增、本期扩展或复用）。
2. **基本信息表**：两列 `项 / 说明`，写方法与路径、认证、生效版本。版本门槛仅在适用时填写；未知信息标为待确认，不能猜测 JWT、版本或路径。
3. **入参**：无新增参数时简写“无新增”，没有入参时写“无”。有参数需要说明时生成 `字段 / 类型 / 说明` 富文本表格，说明中包含位置、必填性和必要约束；即使只有一个参数也使用全宽表格。
4. **返回格式**：先用一句话说明新增/修改/复用的内容，再以完整对象路径为标签，对本次需要说明的业务对象生成 `字段 / 类型 / 说明` 三列表格。项目已有公共响应封装时用一句话沿用，不重复根对象或单字段中间容器的表格；本次变更封装本身时才补对应字段说明。说明中写必要的枚举、条件、单位、默认值与可空性；对象或以业务键为 key 的映射，说明 key 的含义。简单响应只需一张表。
5. **返回示例**：先说明场景和已知 HTTP 状态，再给完整、有效的 `json` 围栏。保留当前项目的实际响应封装、成功码和字段类型；错误、分页或条件分支只补本次相关的示例。
6. **条件说明**：存在条件下发、字段缺省、未命中、空结果或兼容规则时，简述触发条件及客户端依据，与表格和示例一致；没有额外条件时不加空章节。

这规定的是文档结构，不是新 API 契约。参考案例中的字段、返回码、认证及版本不得成为其他项目默认值。接口已复用且没有改动时，简要说明方法、路径、复用范围和不变的契约即可。

**本节所有表格都适用 2.2 样式与全宽要求**：基本信息、入参、返回字段、嵌套对象字段和错误字段表不例外。浅灰加粗居中表头、正文左/顶部对齐，表格总宽均等于同一正文可用宽度；字段少或只有一行时仍保持全宽，不能按内容自适应收窄。

## 新增数据表：沿用 5.1 的 SQL 展示方式

- 标题写编号、“新增 + 用途”与行内代码表名，接完整 `sql` 代码围栏；章节编号服从当前文档，不固定为第五章。
- SQL 写全字段类型、长度/精度、空值、默认值、必要的业务含义注释、主键、唯一约束及查询索引。按目标方言在同一块中放完整建表与必要建索引语句，不用省略号代替字段。
- MySQL/TiDB 项目按已有迁移风格使用字段/表注释、引擎、字符集和适用的扩展；其他数据库使用自己的语法。不能将参考中的特定数据库扩展、参数或默认值复制到未知数据库。
- SQL 本身清楚时，不另加逐字段重复的表格；只补充影响实现、上线或数据一致性的必要说明。参数尚未确认时明确标出，不宣称 SQL 已可在目标环境执行。

## 虚构示例：SQLite 3 项目的任务记录查询

以下示例只展示版式。项目契约明确采用 SQLite 3、`ok/payload/error` 响应，所有字段和版本均为虚构；不是其他项目默认设置。只生成 Markdown 即可完成这一步。

### 3.1 `get_task_record` — 任务记录查询（新增）

| **项** | **说明** |
| --- | --- |
| 接口路径 | `GET /v1/task-records/{id}` |
| 认证 | 需要 JWT |
| 生效版本 | 客户端版本 ≥ 1.4.0 |

**入参：**

| **字段** | **类型** | **说明** |
| --- | --- | --- |
| `id` | integer | 路径参数，必填，任务记录 ID |

**返回格式：** 使用项目现有 `ok/payload/error` 封装，成功返回 `payload.task`；未找到时 `payload=null`，无分页。

`payload.task`：

| **字段** | **类型** | **说明** |
| --- | --- | --- |
| `id` | integer | 任务记录 ID |
| `status` | string | `pending` 或 `done` |
| `created_at` | string | ISO 8601 UTC 创建时间 |

`error`（失败时）：

| **字段** | **类型** | **说明** |
| --- | --- | --- |
| `kind` | string | 错误类型 |
| `detail` | string | 错误说明 |

**返回示例（成功，HTTP 200）：**

```json
{
  "ok": true,
  "payload": {
    "task": {"id": 7, "status": "done", "created_at": "2026-10-12T09:00:00Z"}
  },
  "error": null
}
```

**返回示例（未找到，HTTP 404）：**

```json
{
  "ok": false,
  "payload": null,
  "error": {"kind": "not_found", "detail": "Task record not found"}
}
```

**条件说明：** 成功时 `error=null`；失败时 `payload=null`。客户端按当前项目 `ok` 与 HTTP 状态处理结果。

### 5.1 新增任务记录表 `task_records`

```sql
CREATE TABLE task_records (
    id INTEGER PRIMARY KEY, -- 任务记录 ID
    request_key TEXT NOT NULL UNIQUE, -- 幂等请求标识
    status TEXT NOT NULL DEFAULT 'pending'
        CHECK (status IN ('pending', 'done')), -- 任务状态
    created_at TEXT NOT NULL -- 创建时间，ISO 8601 UTC
);

CREATE INDEX idx_task_records_status ON task_records (status);
```

## 生成与转换验收
