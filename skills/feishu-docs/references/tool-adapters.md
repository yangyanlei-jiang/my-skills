# 工具适配与写入检查

## 已连接的飞书 MCP 或 API

先发现实际可用工具，再读取创建、更新、读取、表格和格式相关的 schema。检查身份验证、目标类型、工具限制、分页和返回内容；不要捏造工具名、JSON 字段或数字块类型。

飞书官方 [MCP 工具清单](https://open.feishu.cn/document/mcp_open_tools/supported-tools?lang=zh-CN) 提供创建、读取、更新、搜索文档等能力，但不同部署和版本暴露的工具可能不同。清单不能证明当前环境已经接入，也不能证明任意原生块都能写入。只使用当前真正提供的工具。

有 Markdown 写入接口时，先核对其具体格式支持。需要原生富文本表格而接口仅支持文本时，改用可用的原生块能力或浏览器；不能只发送管道表格然后报告成功。

更新文档时先解析和确认目标，取得所需内容及分页。某些工具不支持链接锚点定位；不要认为带锚点的 URL 一定能指定可编辑区块。按实际支持的标识和匹配方式定位，出现多个匹配时消除歧义。

遵循当前工具的大小、批量和速率限制。分批写入后记录返回身份。请求结果不明时先读回，再重试缺少的部分。

## 浏览器编辑器

使用当前可用浏览器工具的支持 API。读当前页面及可访问元素，确认文档身份和编辑权限；按照当前 UI 的插入菜单与样式工具栏操作，不固定旧文章中的按钮图标或坐标。

先输入正文，再把真实章节转换为对应标题。表格通过原生插入功能建立，再逐格填充、选择需加粗或加链接的文字。风险使用原生高亮块；代码使用原生代码块并设置语言。

写入后查看实际渲染和必要的结构。若无法确认保存完成或部分格式，应报告具体未确认的项目，不凭编辑动作声称成功。

## 不足以完成任务的能力

仅有纯文本写入、纯文本读取或离线草稿时，不能证明完成了原生富文本格式要求。提供可继续执行的内容和缺失能力说明；如果能取得支持格式的工具，则继续完成用户已授权的工作。

技能不会自动获得登录、文档访问权限或 MCP 服务。账号连接不足时，只询问完成任务所需的最少信息，不要求用户提供密钥到对话中。

## 修改边界和验收

- 编辑前记录目标区域的现有结构，准确定位块或单元格。修改一个表格单元格时，保留其他单元格和该区域之外的内容。
- 文字改动尽可能保持原有富文本片段，尤其是链接目标和加粗范围；不要将富文本对象整体降级成字符串。
- 新建文档成功返回的 URL 应可对应到实际对象。工具只有内部 ID 时，按其官方支持的方法取得链接，不编造地址。
- 验收证据可以来自结构化读取、可靠的格式结果或浏览器渲染；没有样式信息的纯文本不足以验收表格、下划线或高亮块。
- 提及人员需要确认唯一身份，并检查是否会产生通知。不要主动添加未经请求的提及、修改分享权限或发送消息。
