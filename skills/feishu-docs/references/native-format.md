# 原生格式映射

“原生”指飞书文档中真实的内容块或行内样式。下面的块名称用于描述能力，不是可以直接发送的 API 枚举或字段名。具体字段、限制和 ID 必须从当前工具契约取得。

| 内容意图 | 应使用的格式 | 验收重点 |
| --- | --- | --- |
| 文档名称 | 文档标题字段 | 标题正确，正文无不必要的重复标题 |
| 章节 | 原生标题及层级 | 标题级别、目录和内容层级一致 |
| 普通解释 | 正文段落 | 未错误进入目录 |
| 重点词句 | 加粗、支持的文字高亮或下划线 | 指定文字的行内样式实际存在 |
| 并列项、步骤 | 无序、有序列表 | 实际列表类型和缩进正确 |
| 待办 | 原生任务列表 | 状态正确；负责人、期限另查任务能力 |
| 引用 | 引用块 | 未误写为正文或提示块 |
| 风险、提示 | 原生高亮块 / callout | 真正的块类型，支持时设置适当图标和颜色 |
| 数据对比、负责人与状态 | 文档富文本表格 | 原生表格、行列数、各单元格与样式 |
| 代码 | 原生代码块及语言 | 代码原样保留，语言正确 |
| 图表、公式 | 当前可用的图表块、插件或公式块 | 实际渲染；不以源码文本冒充 |

## 富文本表格样式：沿用参考 2.2

用户指定参考文档 2.2 的表格已于 2026-10-12 通过原生结构与渲染画面核对。只继承样式，不复制其业务分类、字段或数据，也不固定为四列或四条记录。

- 使用可编辑的文档富文本表格；单行表头，浅灰背景，表头文字加粗、水平居中。
- 数据单元格保持白底，正文左对齐、顶部对齐、自然换行；行内代码、链接和必要强调保留富文本。
- 使用原生表格的细浅灰网格边框和紧凑行距，不堆彩色底纹、空白行或装饰性合并。
- **文档所有表格的总宽度一致，并铺满正文可用宽度。** 包括接口基本信息、入参、返回/错误字段、规则、对照及其他表格；两列、三列或更多列都与正文左右边界对齐，只有一行数据也不收窄。不是铺满浏览器窗口、侧栏或页面边距。内部列宽按短标识与长说明分配，各列总宽度等于正文可用宽度，不能使用按内容自动收窄的整表宽度，也不能横向溢出。
- 沿用目标文档现有普通/宽版布局；用工具契约或当前文档取得正文可用宽度，不为表格更改整篇布局，不写死某个历史像素值。生成时已知正文宽度且转换器支持列宽，就在 Markdown 扩展中直接表达；未知或不支持时将统一全宽列入补齐清单。
- 行列数和列名取决于实际内容；多字段规则/对照可以组织为“分类、对象、条件、说明”等列，接口仍按其基本信息表与字段表组织。
- 编辑已有单元格时保留既有表格样式；仅新建表格或用户要求重排的目标表应用此样式，不顺带重排其他表格。

### 在 Markdown 生成阶段表达

基础管道表格先写齐内容和 `**加粗表头**`。普通 Markdown 没有通用的单元格背景或“表头居中、正文左对齐”独立样式，不能将对齐分隔符或未确认的 CSS 视为完成这些样式。

目标链路明确支持飞书官方 CLI 的 Markdown 内嵌 XML 时，可按其 [表格语法](https://github.com/larksuite/cli/blob/main/skills/lark-doc/references/lark-doc-xml.md) 在 `.md` 中直接表达浅灰表头、对齐和富文本。以下使用虚构数据，并假定目标正文可用宽度已确认是 960 像素；实际输出不转义标签，也不把它围在代码块中：

```xml
<table>
  <colgroup><col width="120" /><col width="180" /><col width="240" /><col width="420" /></colgroup>
  <thead><tr>
    <th background-color="light-gray" vertical-align="middle"><p align="center"><b>阶段</b></p></th>
    <th background-color="light-gray" vertical-align="middle"><p align="center"><b>输入</b></p></th>
    <th background-color="light-gray" vertical-align="middle"><p align="center"><b>判断条件</b></p></th>
    <th background-color="light-gray" vertical-align="middle"><p align="center"><b>处理方式</b></p></th>
  </tr></thead>
  <tbody><tr>
    <td vertical-align="top"><p align="left">校验</p></td>
    <td vertical-align="top"><p align="left">请求参数</p></td>
    <td vertical-align="top"><p align="left">必填项齐全</p></td>
    <td vertical-align="top"><p align="left">继续处理</p></td>
  </tr></tbody>
</table>
```

以上仅使用该工具当前定义的属性，不假设任意 HTML/CSS 被转换。该工具支持在 `<table>` 后用 `<colgroup><col width="..." /></colgroup>` 定义列宽；示例各列之和为 960，实际生成时替换为目标正文宽度，所有表的列宽总和一致。不要猜测 `<table width="100%">` 或 CSS 能被转换。默认原生边框与实际宽度仍需读回或渲染确认。

只支持基础 Markdown 时，生成完整管道表格，并将“浅灰表头、表头居中、正文左/顶部对齐、所有表格统一全宽”等当前链路尚未表达的样式记到独立补齐清单。转换后优先批量设置原生样式与宽度，必要时最后一次浏览器局部调整；不重新建表或逐格重填已转换的数据。只生成 `.md` 时交付这份清单，不为补样式登录飞书。

## 富文本表格流程

首先在 Markdown 中生成完整表格，并使用支持的转换链路。以下原生操作用于无法由 Markdown 表达或转换缺失的部分；已正确转换的基础表格不重新逐格建立。

1. 从数据计算行列数，表头算一行；不要为视觉留白创建无意义的空行。
2. 查清当前工具如何创建文档表格、读取单元格以及写入单元格富文本。查明允许的大小、嵌套和合并能力，不猜测限制。
3. 创建表格后读取返回的表格及单元格身份。浏览器中则插入原生表格，再逐格确认位置。避免假设表格 ID 能直接作为单元格 ID。
4. 按行列填入内容，按上述 2.2 样式设置新表格。链接保留目标 URL，指定样式保留为实际富文本元素。编辑时保留未修改内容的原有富文本。
5. 读回或查看 UI，核对原生表格、预期行列数、每个单元格、浅灰/加粗/居中表头、正文对齐换行、边框与关键富文本；同时确认全部表格总宽度相同、与正文左右边界对齐、没有溢出或被裁切的列。

例如“项目 / 负责人 / 状态”加两条项目数据应为 **3 行 × 3 列**。带制表符的三行文本只是数据来源，不能算作已经写好的表格。

飞书的“文档表格”和“电子表格”是不同对象。不要为满足原生富文本表格要求创建 Sheets、嵌入电子表格或 Base。

## Markdown 的边界

- 编辑器的 Markdown 快捷键只支持特定转换。官方说明明确：不能通过输入 Markdown 语法插入表格。
- 连接器或导入 API 的 Markdown 能力由其自己的契约决定。只有明确支持生成原生表格时，才能用管道表格作为中间输入；随后检查真实结果。
- 双下划线通常表示强调，不能当作通用的下划线语法。飞书编辑器的快捷语法也不能直接套在 API 上；目标支持 `<u>` 等扩展时在 Markdown 中直接表达，否则最后设置显式下划线属性。
- 代码块中的 Mermaid 源码不会自然变成图表。查清插件或工具是否能创建并渲染 Mermaid；若仅能存放代码，明确这一限制。
- 不使用空格对齐、大号标题或未确认支持的 HTML/XML 替代所需格式。目标明确定义的飞书扩展可作为转换输入，详见 [Markdown 工作流](markdown-workflow.md)。
