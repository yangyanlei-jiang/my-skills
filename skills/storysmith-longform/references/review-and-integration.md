# 审稿次序与现有工具衔接

## storysmith 兼容边界

保持 analyze / aggregate / create / review 的任务分界，区分观察、推断、建议与继承证据。本技能增加长篇多尺度结构与逐本证据，不修改原技能，不搬入其短篇/期刊视觉样本，也不合并样本分母。共同使用时读取当时实际可用版本；旧技能不存在、已变更或不可访问时不假称调用。

## 不覆盖既有技能

保持 storysmith-longform 独立。只有实际可读取某项技能时才按其当前说明调用；不得宣称已接入、继承或执行一个未读取的技能。用户明确点名其他技能时，先定位并读取它。以下是职责分工约定，不是对未核验软件接口的描述。

- storysmith/原有创作流程：保留用户选定的总体工作方式；本技能提供长篇证据分析和结构判断，不替换原技能。
- OhStory：若可用，让其承担连续性与设定账；输入已确认事实、当前章节、拟改动，检查时间、知识、能力、位置、物品和承诺是否冲突。
- Sepia：若可用，让其做独立审稿；给稿件、目标读者、当前意图和不能改动的事实，不先喂预设判决。
- human-writing：若可用，在结构与事实稳定后做语言自然度润色；保留角色声音、必要重复、留白和叙述节奏，不把文本改成统一“人味”腔。

若依赖不可用，使用下方显式检查完成相应工作，并标为本次检查，不能伪称运行该技能。

## 三轮检查

### 第一轮：结构与连续性

检验因果断裂、角色动机缺口、信息/能力越权、未付出的代价、关系突然转向和承诺丢失。定位到具体章/段；分开“已证实矛盾”和“需前文补证”。提出最小有效修法，说明是否影响后文。

### 第二轮：场景与阅读效果

检验视角是否稳定、对白是否体现双方意图、说明是否阻断当前行动、情绪转折是否获得铺垫、悬念是否建立在真实问题上。保留休息、生活感和不服务主线的有意纹理；不能把一切都压成情节效率。

### 第三轮：语言与留白

检查空泛抽象、同义叠加、修辞互相遮挡、段尾解释、模板转折、节奏单调与角色口吻趋同。只报告本稿真实存在的模式，并给局部改法；不要将特定词当 AI 判定器。为审美分歧提供可选方案，避免把个人喜好包装成硬错。

## 交付优先级

按“会改变读者理解/后续因果的错误 → 降低可信度的执行问题 → 可选风格优化”排序。每条包含位置、现象、影响、修改建议和改动边界。用户只请求审稿时不自动重写；请求润色时不自动重构剧情。较大修订先展示影响面与方案，再按授权执行。

## 通过条件

稿件的核心意图仍清晰；重大连续性冲突已解决或明确待核；关键选择存在原因与代价；前文承诺有当前状态；语言修改没有抹平人物差异或提前揭示谜底；所有外部工具/技能调用均与实际执行一致。未满足的条件须如实报告，不用总分掩盖阻断问题。
