# YYL Code Style

让实现自然融入杨艳磊的代码。当前任务、仓库规则和真实接口契约优先；个人风格决定表达方式。历史样本是参考，不是当前项目的事实。

## 开始修改

读取目标附近的实现、直接调用方和格式配置，确认输入、输出及当前层的职责；定位方式遵循仓库指引。小改动只补齐与它有关的上下文。

- **新增功能**：复用已有实例入口、校验器、常量和分层；用最少的职责拆分表达业务。
- **重构/修复**：按任务范围修改，保留旧签名、nullable、弱类型调用和客户端兼容；范围外的风格差异不顺手整理。
- **基类改动**：优先在业务类、子类或现有扩展点解决问题，不为局部需求或风格统一轻易修改共享基类。确有必要时，先核对受影响的子类与调用方；修改前在会话中明确说明涉及的基类/方法、修改原因和影响范围，完成时再次列出实际改动、验证结果及未验证的范围。
- **只读审查**：给出位置、触发条件、影响和建议。契约/正确性问题与可选风格建议分开，未经要求不落地修改。

缺少会改变接口或数据行为的事实时，先查调用方/现有实现；仍不明确才提出具体问题。模板中的类名、参数、阈值、响应与表结构都是示例假设。

## 默认表达

- PHP 类/命名空间 `PascalCase`，方法/变量/属性 `camelCase`，数据库/API/配置键沿用 `snake_case`；其他语言先遵循其现有规范。
- 四空格、短数组、英文标识符、中文业务注释。formatter 和邻近文件优先；无规范的新 PHP 代码采用 `[ 'key' => $value ]`，多行关联数组适度对齐 `=>`。
- 前置校验、提前返回、循环中 `continue`；先收集、批量读取，再显式组装结果，保持顺序、重复项和空值语义。
- 注释说明业务原因、边界或兼容性；职责不明时补 PHPDoc。不生成作者日期头、逐行翻译或注释掉的旧代码。
- 新内部方法按目标运行时补明确类型；不为风格给旧文件添加 `strict_types`、收紧接口或批量迁移 enum。复用既有常量，新常量用明确的 `UPPER_SNAKE_CASE`。
- 保留框架原有 DI、生命周期和分层。只有独立职责确实需要时才拆类，不因套模板新建 Repository、单例或响应外壳。

## 完成前

- [ ] 差异限于任务范围，命名、格式、层次与附近实现一致。
- [ ] 若修改基类，已确认必要性、检查影响范围，并在会话说明和最终交付中明确披露。
- [ ] 输入、鉴权/数据范围、输出类型/顺序/空值和旧调用方仍符合实际契约。
- [ ] 查询按需批量处理；涉及错误或副作用时，已按对应参考检查失败传播、事务和重放。
- [ ] 验证针对改动的行为；PHP 修改逐文件 `php -l`，行为检查沿用项目方式，不自动搭建测试框架或执行 schema/migration。

交付说明改了什么、实际验证及尚未确认的边界；不要将语法检查或内存替身说成生产集成验证。
