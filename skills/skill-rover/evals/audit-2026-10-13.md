# SkillRover v0.3.0 可行性与设计审查

审查日期：2026-10-13。基线为 my-skills 的 `3f0d403`，SkillRover 运行时版本为 0.2.0。审查覆盖实际代码、既有评测、临时文件复现、修复回归和宿主接入契约。

## 结论

**作为宿主智能体驱动的技能路由与生命周期管理层，方案可行；最初的目标已部分达到。** 可复现的价值在于首次加载计时、使用占用保护、身份绑定的替换证据、托管副本退役，以及路由是否登记的可观察性。

“自动选到最合适的技能”仍由宿主模型判断，尚未建立优于宿主原生选择的可靠对照数据。安装 skill 本身不会强制每次执行路由；hook 提供指引，模型必须实际调用 `use` 或记录无需技能的原因。`doctor` 和记录能帮助排障，不能证明语义选择正确。

| 原始目标 | 当前结果 | 证据与边界 |
| --- | --- | --- |
| 项目本身也是可安装的 skill | 达到 | SKILL.md、引用资源和 Python helper 自包含 |
| 优先已安装技能，能力不足再搜索外部 | 流程达到，效果待量化 | 指令与 GitHub 搜索/不可变提交下载可用；helper 不负责语义排序 |
| 复杂任务自动触发 | 有宿主条件 | 空目录也收到路由 hook；未信任、未支持或未遵循时不能保证执行 |
| 加载固定时间后复评 | 机制达到 | 默认 24 小时从首次成功加载起；重复加载不延期；到期后的下一次宿主事件触发提醒 |
| 发现更合适技能后切换 | 机制达到 | 要求实际验证、绑定 ID/内容哈希的证据和旧技能无活跃占用 |
| 卸载旧技能 | 托管范围达到 | 只退役和归档托管副本；不删除用户原始安装，也不能清除模型已有上下文 |
| Codex、Claude Code 通用 | 共享核心，宿主适配分别验证 | 配置与原生运行结果分开记录；没有 Windows 实机结论 |

## 已修复的问题

1. **替换提前启动加载时钟。** 旧实现将尚未加载的候选标记为已加载，提前产生复评时间，也使已加载数量失真。现在安装/替换不会冒充首次加载；真正读取后才开始计时。已加载候选在完成替换比较后开启下一周期。
2. **读取失败留下虚假占用。** 原 CLI 先登记加载，再读取 SKILL.md。读取失败后会留下加载时间和使用占用。现在在同一状态事务中先完成有界 UTF-8 读取，再登记，CLI 直接返回读取结果。
3. **项目接入可能写到选定项目之外。** `.claude`、`.codex`、`.agents` 或 skills 父目录是符号链接时，原安装器可能改写链接目标。现在写入前拒绝这些项目内链接；明确选择的项目根目录别名仍支持。
4. **重新接入产生重复 hook。** 改 Python 或 state 路径时，原实现只追加新 handler。现在精确识别同一脚本的标准生成 handler，更新并去重；保留自定义/带过滤器/其他脚本的配置。
5. **嵌套状态损坏破坏 fail-open。** 损坏的时间、占用列表和提醒时间曾导致 traceback 或继续使用无效状态。现在在读取时诊断并保留原文件，hook 返回 `{}`；超大整数也被覆盖。
6. **缺少直接的接入诊断。** 新增只读 `doctor`，报告项目配置、状态路径、待完成路由和待复评情况；不执行配置命令、不登记技能、不推进复评时间。独立复审进一步修复了合法大配置误报和新旧 hook 并存漏报。

## 本次验证

- 基线 62 项 Python unittest 通过；修复后 **83 项通过**，本地 Python 3.12，另运行生命周期示例。
- 新增用例先在未修复实现上观察失败，再实施修复。使用真实临时项目和 CLI 子进程；指令读取失败使用文件读取边界故障注入。
- 完整测试覆盖并发回合登记、会话结束、忙碌技能拒绝替换、来源保留、到期边界、归档恢复；本次没有将它们等同于模型效果评测。
- 两个独立审查分别检查生命周期及接入代码；发布复审提出的 3 项问题均已修复并复查通过。
- 官方 hook 文档核对了 Codex 项目路径/事件/SessionEnd 超时及 Claude 的 exec-form 参数；生成命令通过子进程测试。

此前原生运行和行为样本见 [初版记录](report.md)、[自动路由记录](automatic-routing.md)。没有重新运行完整 30 场景双宿主基准，不声称路由准确率、成本或成功率提高。

### 本次原生宿主烟测

使用隔离的临时项目、生成的项目 hook 和合成技能/输入。未修改全局配置或凭据，未跳过宿主审批、沙箱或 hook 信任机制。

| 宿主 | 实际观察 | 不能据此声称的能力 |
| --- | --- | --- |
| Codex CLI 0.155.0，macOS | 普通外层沙箱内因 app-server EPERM 提前退出；获准的外层环境重试后启动会话，hook 留下 1 次待完成路由与会话结束记录；默认模型被当前 CLI 账号返回 HTTP 400 拒绝，未擅自更换模型 | 未获得模型完成任务、技能登记或端到端替换证据 |
| Claude Code 2.1.281，macOS | 普通外层沙箱限制 session-env 创建且模型请求失败；获准重试后观察到 SessionStart、UserPromptSubmit、PostToolUse 成功，并原生调用 SkillRover 和合成测试技能、读取输入；非交互运行中的普通审批阻止 helper Bash 和产物 Write | 未完成托管登记/产物写入，不能宣称整个自动流程成功 |

这些结果把原生事件送达、技能激活与最终任务成功分开。测试允许宿主为这些临时会话写入正常运行日志/会话环境，但不更改安全配置。不同账号、模型权限和宿主审批模式仍需分别验证。

## 周期建议与后续优化

**保留默认 24 小时。** 它是工程默认值，没有数据支持唯一最优周期。稳定工作流可设 168 小时，活跃试验可设 1 小时；任务变化或失败仍可通过 `mark-due` 提前请求比较。搜索失败或没有完成比较时保持待复评，不为清空提醒而调用 `keep`。

后续优先级：

1. 用真实任务建立基线/SkillRover 配对评测，记录任务质量、错误选用/漏选、调用开销与替换收益，确定什么时候路由值得触发。
2. 给 `keep` 增加可选结构化 task/candidates/checks 记录；当前 reason 只是宿主的完成声明，不能自动验证比较的真实性。
3. 为大规模长期使用设计历史保留/压缩策略。现在状态 JSON 随历史增长，不适合无边界地当遥测数据库使用；避免高频重复加载同一技能。
4. 版本化 bundle digest 后再加入执行权限元数据。现有哈希验证相对路径和文件内容，**不包含可执行位**；直接改变算法会使旧包全部失效。本版保持兼容，执行脚本仍应验证实际依赖/权限。
5. 补充安装状态提交失败后的孤立包恢复。复制成功而状态落盘失败可能留下未登记目录；不能盲删，因为 fsync 报错可能发生在实际提交之后。当前不会把未登记目录当作可用技能。
6. 完成 Windows 宿主、原生端到端替换和更大样本的隐式触发验证。
